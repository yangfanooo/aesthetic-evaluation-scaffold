# 落地页排版评测标准（候选 v0.1）

状态：候选。没有样本校准，不能当作已验证标准。  
核查日期：2026-10-28。  
维度：排版。物料：落地页（营销或产品介绍用的纵向滚动单页）。

本文件只评排版。配色、图形与摄影品质、文案内容、品牌识别、转化效果、动效趣味，都不进入本维度分数。字号、字重、行距、行长、对齐、间距和跨视口重排属于排版。字体“好不好看”不评分；只有当字体设置破坏层级或正文阅读时，才记为排版问题。

---

## 1. 输入范围

### 1.1 已知

- 设计维度是排版，物料是落地页。
- 没有提供品牌栅格、字号规范或必须遵守的设计要求。因此本版只有工艺判断，不单列“是否符合某份规范”的遵从分。
- 落地页是纵向阅读的长页面，至少会在桌面和手机两种宽度下被看到。排版要同时看版面关系和文字设置。

### 1.2 暂定

实施前可以按下列假设运行；用户改口后，只改对应分支，不改质量边界。

| 项 | 暂定 | 改口后如何处理 |
| --- | --- | --- |
| 页面状态 | 字体加载完成、懒加载内容已出现后的稳定版面 | 若要评加载过程或打开菜单、弹层，另设状态，不并进本次分数 |
| 视口 | 桌面 1440×900，手机 390×844 | 只评其中一个视口时，另一个视口记为不适用 |
| 语言 | 简体中文横排，允许夹有英文 | 纯英文走西文行长分支；直排本版不适用 |
| 完整产物 | 整页，含首屏以下各节 | 只有首屏截图时，页下各节未判定 |
| 材料 | 优先可打开的页面；其次整页截图 | 材料不同，证据不同，见技术方案 |

### 1.3 明确不评

- 颜色对比。文字与背景混到无法定位字形时，相关角度证据不足，记未判定。这不是排版 0 分。
- WCAG 文本间距覆盖测试。该条款要求用户把行高调到 1.5 倍等数值后内容不丢失，并不要求页面本身使用这些数值。
- 书籍版式里的首行缩进两字、段间不加空行。落地页常用段间距分区，不因此扣分。
- 业务目标、点击率、品牌口号是否正确。

## 2. 评测角度

五个角度各判断一件不同的事。同义现象合并，不同判断拆开。

### A. 阅读层级

看标题、说明、正文、行动文字是否用尺寸、字重和位置排出可扫描的顺序，以及这个顺序能否沿整页重复。

落地页先被扫读。层级决定人能否先看见主信息，再进入下一节。它不判断某一段正文好不好读，也不判断左右边缘是否对齐。

### B. 正文文字设置

看承担连续阅读的文字：字号是否成段可读，行距是否稳定，一行里的字数是否让视线能回到下一行，换行是否把词和标点拆坏。

层级可以正确，正文仍然难读。所以与 A 分开。按钮上的两三个字、价格数字、导航短标签，不按正文行长判断。

### C. 对齐与栏结构

看文本块、卡片、图片是否共享可重复的对齐轴和内容宽度。故意重复的错位，如果在同类模块里用同一套偏移，算结构，不算失误。

对齐成立时，间距仍可能混乱。所以与 D 分开。

### D. 间距与分组

看同类关系是否使用同类间隔，相关内容是否比无关内容更近，节与节之间是否有稳定节奏。

这是间隔系统，不是“留白越多越好”。单个元素内部的行距归 B，不归 D。

### E. 视口内排版完整性

看纳入评测的每个视口里，文字和区块是否完整落在可读范围内：没有非预期横向溢出，没有文字互相重叠或被容器裁掉关键字，窄宽度下栏结构重排后 A–D 仍然成立。

桌面排得好、手机溢出，是本角度的问题。地图、数据表、必须横向浏览的素材，允许局部双向滚动，不把这种局部区域算作整页溢出。

## 3. 评测标准

### 3.1 问题只归一个角度

| 观察到的事实 | 归入 | 不再计入 |
| --- | --- | --- |
| 标题和旁边说明的字号、字重分不开 | A | B |
| 正文行距过紧或一行字数失控 | B | D |
| 一排卡片左缘或右缘对不齐 | C | D |
| 卡片之间间距忽大忽小，或节与节分不开 | D | C |
| 文字重叠、被裁切、页面横向溢出 | E | 不因同一几何事实再记一次 C 或 B |
| 手机把桌面的多栏重排后，标题顺序消失 | E 记录触发位置；层级事实仍由 A 定性 | 不另造第六个角度 |

同一事实只降一次档。

### 3.2 严重度

严重度服务定分，不单独打分。

**阻断。** 主视口里，主标题或主要正文因重叠、裁切而读不完；或者非预期横向溢出截断主要内容；或者整页无法区分标题和正文，也看不到分组。

**严重。** 首屏，或两个以上主要区块，层级分不开；同类区块的对齐轴不成立，且不是重复使用的故意错位；多个正文块行距粘连，或行长明显失控；间隔无法区分“同一组”和“下一组”；纳入评测的手机视口出现溢出或重叠。

**明显。** 能指出具体小节：某一节间距失控、某一组卡片没对齐、某一段正文行长过长、某个次级标题偏弱。首屏主路径和多数区块仍然清楚。

**轻微。** 个别次要文字行长略长，或一两处不影响阅读的边缘偏差。整页完成度还在。

像素级容差暂定为 2px，只用于把亚像素取整和真正错位分开。这个数没有样本校准，校准前不得单独决定档位。

### 3.3 角度执行规则

#### A. 阅读层级

- **判断目标。** 页面是否存在可重复的字号阶梯，扫描时能否先看到该节最重要的文字。依据是排版工艺，不是某份品牌规范。
- **输入。** 稳定态整页；桌面与手机两个视口。需要每个可见文字块的字号、字重、位置，以及它所在的节。短标签可作层级证据，不作正文证据。纯图形首屏若文字在图片里，改由截图观察，并注明测不到计算字号。
- **步骤。**
  1. 标出首屏的主标题、辅助说明、行动文字，以及其后每个主要节的节标题和节内正文。
  2. 记录它们的字号、字重和相对位置。
  3. 检查是否至少形成三档可区分的角色，例如主标题、节标题、正文。两档也可能成立，但必须在整页稳定复用，并且主次不会看反。
  4. 沿页面向下看，节标题是否用同一角色进入下一节。
  5. 若两段文字字号接近，看字重、位置和周围间隔是否仍能分出先后。分得出，记为成立；分不出，按出现范围记入明显或严重。
- **输出。** 字号阶梯清单、首屏阅读顺序、失效节的位置。对应关系：全页阶梯清楚且重复使用，支持 4 分以上；能指出被贯穿的阶梯如何引导长页扫描，是 5 分的必要证据之一；首屏或两节以上失效，为严重；仅个别次级标题偏弱，为明显。

边界：海报式大标题、正文很少，只要主信息和次信息分得开，A 可以成立。B 对不存在的长段落不适用。

#### B. 正文文字设置

- **判断目标。** 连续阅读的文字是否能逐行读完。中文依据 W3C《中文排版需求》对行距的公开说明；西文行长依据 Butterick 的公开排印建议。二者都是工艺参考，落地页尚未用样本校准，数值先作观察带，不单独锁定档位。
- **输入。** 段落、说明文字、卡片内的多行说明。每个文字块需要字号、行高、行数、每行字数、是否溢出容器。导航、按钮、价格、单行标题不适用本角度。
- **观察带，校准前使用。**
  - 中文行距：版心行距多为字号的 50%–100%，且各行一致。换算到 CSS，行高约是字号的 1.5–2.0 倍。行距可以因行长短、字号小而取带内较低值。行距大于字号，通常不增加易读性。来源是书籍版心需求，网页落地页只借用“稳定、不粘连、不异常松散”。
  - 西文行长：Butterick 建议平均一行 45–90 个字符。这是拉丁文字建议，不直接套到汉字。
  - 中文一行字数：现行《中文排版需求》要求行长与两端对齐原则，没有把某一字数区间写成已发布要求。17–40 字、横排不宜超过 48 字，只出现在 W3C 讨论稿，本次不作为扣分线。
  - 字号没有采用固定及格线。桌面正文小于 14px、手机正文小于 15px，只记为风险事实；必须同时看到粘连、溢出或成片难读，才上升为严重。
- **步骤。**
  1. 列出所有连续阅读文字块，跳过短标签。
  2. 计算行高与字号的比值。中文正文若明显低于 1.5，或西文正文明显低于 1.2，先记为风险，再看字形是否粘连。
  3. 统计每行字数。西文多个段落稳定超出 90 字，或中文多个段落一行长到回行困难，记为行长问题。中文的具体字数线等校准后写入。
  4. 看换行：英文单词被拦腰截断、中文标点反复出现在行首、文字溢出盒子。个别标点在行首记轻微或明显；成片出现并影响阅读，记严重。
  5. 左对齐、右边缘不齐，在网页落地页上成立，不扣分。
- **输出。** 文字块位置、行高比、每行字数、粘连或溢出截图。多个正文块同时难读，为严重；只有一段过长，为明显；风险数值存在但阅读仍然顺畅，为轻微，不得单独压到 3 分以下。

#### C. 对齐与栏结构

- **判断目标。** 同类元素是否共享对齐轴和内容宽度。依据是版面工艺。Miniukovich 与 De Angeli 2015 年把“对齐点数量、块尺寸种类”用作界面美学指标；本次只把它们当作取证线索，不把论文里的回归结果换成分数。
- **输入。** 各文字块、卡片、图片的边界。需要整页，否则只能判断可见部分。
- **步骤。**
  1. 按节分组，提取左缘、右缘、中心线。
  2. 合并相差不超过 2px 的轴。
  3. 同一节里角色相同的元素，应落在同一组轴上，或落在一套重复出现的偏移上。
  4. 检查内容宽度：正文栏、卡片列在各节是否复用同一宽度。有意的宽窄交替，只要每次交替使用同一组宽度，算结构。
  5. 区分单次失误和全页没有栏。前者可以是明显；后者若导致区块无法对应，是严重。
- **输出。** 对齐轴清单、偏离元素及偏离量、是否属于重复错位系统。

边界：不对称首屏可以得高分。条件是偏移被重复使用，阅读顺序仍然清楚。只出现一次、和其他模块对不上的错位，记为问题。

#### D. 间距与分组

- **判断目标。** 间隔是否表达归属。相关项更近，节与节更远，同类关系用同类间隔。
- **输入。** 节与节、卡片与卡片、标题与所属正文、正文与行动文字之间的间距。行距不在这里重复计算。
- **步骤。**
  1. 列出上述四类间隔的像素值。
  2. 看同类间隔是否聚成少数几档。差在 2px 内视为同一档。
  3. 看每一节内部，标题到正文的距离是否小于本节到下一节的距离。
  4. 卡片网格中，组内间距应稳定。某一行突然变大，而内容关系没有变化，记为明显。
  5. 若相关项和无关项的间隔没有差别，分组失败。出现在首屏或两个以上主要区块，记为严重。
- **输出。** 间距档位、分组失败的位置。全页只有一两档有规律的间隔，并且节距稳定，是 5 分所需的间距证据。间隔大体均匀、只有轻微偏差，支持 4 分。

#### E. 视口内排版完整性

- **判断目标。** 在每个纳入评测的视口中，排版是否完整。桌面宽度下的横向溢出，引用 WCAG 2.2 的重排说明作为公开参照：纵向阅读的页面不应再靠左右滚动来读正文。默认手机宽度是 390，不是 320。只有用户把 WCAG 列为约束时，才追加 320 CSS 像素检查。
- **输入。** 每个视口的稳定态整页；文档是否出现横向滚动；文字盒子是否相交；文字是否被 `overflow` 裁切。固定定位的顶栏单独记录，不把顶栏本身算作溢出。
- **步骤。**
  1. 在每个视口等待字体和懒加载完成，再测量。
  2. 找出伸出视口、且没有被祖先裁切的元素。伪元素溢出、固定定位元素需要单独看，脚本可能漏掉。
  3. 找出文字盒子相交，以及文字被容器裁掉后语义不完整的位置。
  4. 在手机宽度看多栏是否变成可阅读的纵向顺序，A–D 的结论是否仍然成立。
  5. 地图、表格、代码块等本来就需要横向空间的局部区域，单独注明，不上升为整页阻断。
- **输出。** 视口、溢出元素、重叠位置、重排后失效的节。手机视口的严重溢出或重叠，把整页最高分限在 2 分。只提供了一个视口的材料时，另一个视口未判定，不视为失败。

### 3.4 分值判据

分数描述整页排版这一件事。五个角度不各自打分，也不取平均。

**5 分：完成度出色。**  
A–E 都没有明显、严重或阻断问题。除此之外，页面上能指出一套被实际使用的空间系统：字号角色沿各节重复，同类间距成档，节标题以稳定方式进入下一节，正文栏宽在各节一致；手机把栏重排之后，这套关系还在。大标题很少、留白很多、装饰很少，只要这套系统指得出来，就可以是 5 分。

**4 分：完成度稳定。**  
主路径清楚，正文能读，对齐和分组成立，纳入评测的视口没有溢出和重叠。允许轻微问题。与 5 分的差别是：页面干净、合格，但指不出贯穿全页的字号阶梯和间距档，节与节的进入方式不稳定。

**3 分：基本成立，有明显局部瑕疵。**  
整页仍能阅读和扫描，至少有一处明显问题，没有严重问题和阻断问题。例如某一节卡片没对齐，或某一段正文行长失控，首屏和其他节仍然清楚。

**2 分：存在严重质量问题。**  
至少有一条严重问题。页面仍能看出区块和原本的阅读意图。与 3 分的差别是：问题落在首屏主路径，或在两个以上主要区块重复出现，改一处局部不能恢复整页。桌面完好、手机严重溢出，也是 2 分。

**1 分：已实现但不可用。**  
页面有文字和区块，但至少有一条阻断问题，核心阅读不能成立。与 2 分的差别是：2 分还能辨认结构，1 分已经不能靠这个版面读完主信息。

**0 分：明确未实现。**  
只在一种事实上使用：评测对象应当是一张可阅读的落地页，但稳定态取证后没有可观察的内容结构。空白页、加载失败后的空文档、主要内容全部不可见，属于这种情况。少一个模块、使用了大图首屏、没有某个按钮，都不能判 0 分。

### 3.5 定分步骤

1. 确认本页适用排版评测。纯无文字、且用户声明本就不做排版的影像页，记不适用。
2. 核对必要证据：至少一个主视口的整页稳定态，能看见文字和区块。不足则未判定。
3. 按 A–E 取证，每条问题只归一个角度，并标成轻微、明显、严重或阻断。
4. 先看 0 分事实。成立则给 0，并停止。
5. 有阻断，给 1。
6. 没有阻断、有严重，给 2。其他角度表现好，不升档。
7. 没有阻断和严重、有明显，给 3。多条明显问题仍然是 3，不累加成 2。
8. 只有轻微问题或没有问题：能指出第 5 档要求的空间系统，给 5；指不出，给 4。
9. 不适用的角度不参与降档。未判定的必要角度使整页未判定。
10. 两名评审事实不一致时，回到截图、盒子和计算样式复核。事实一致但档位不同，对照 5/4、3/2、1/0 的差别条款。仍然不一致，整页未判定，不取平均，不把模型置信度折成分数。

### 3.6 异常处理

| 情况 | 记录 | 分数 |
| --- | --- | --- |
| 用户声明只做桌面 | 手机不适用 | 只按桌面定分 |
| 只有桌面截图，手机未知 | 角度 E 的手机部分未判定 | 整页未判定 |
| 工具打不开页面 | 记录原因，先查网络、登录、拦截 | 未判定，不是 0 分 |
| 字体未加载就截图 | 证据无效，重新等到字体就绪 | 未判定 |
| 文字颜色导致无法定位字形 | A、B 证据不足 | 相关部分未判定 |
| 评审对“故意错位”有争议 | 检查偏移是否在重复模块中复用 | 未解决则未判定 |

运行中不删角度、不补分、不临时加权，也不按剩余角度重新平均。

### 3.7 校准

本版是候选。校准至少包含这些样本：清楚的高完成度长页、稳定但普通的页面、只有局部瑕疵的页面、首屏层级失败的页面、手机溢出的页面、故意不对称且形成系统的页面、中文长正文、英文长正文、文字烧在图片里的首屏、空白或加载失败页。

制定标准的人不参加试评。试评重点看 5 分是否被“没有挑出问题”误判，以及不对称风格是否被压低。修订后形成新版本，旧样本按新版本重评。

### 3.8 两种用法

产物评测和交付前检查使用同一套质量边界。

交付前检查还要事先写明：只允许改字号、行高、宽度、对齐和间距；文案含义不动。每次修改后，用同一版本标准复查整页和全部纳入视口。可修改次数、时间和成本上限由任务方在开始前给定。未给定上限时，不进入自动修改。达到上限、证据不足或出现要求冲突时停止，交给人处理。

## 4. 检测技术方案

工具输出是证据，不是分数。分数只按第 3.5 节产生。

核查日期均为 2026-10-28。未实际跑样本，性能数字不写。

### 4.1 路线 A：页面测量取证，人工定分

**适用。** 有 URL 或可在浏览器打开的页面。这是首选。

**实现。** 使用 Playwright 打开页面。许可证 Apache-2.0，维护方为微软，仓库仍在更新。官方说明支持在页面内执行脚本并取回结果，也支持整页截图。实施时：

1. 设置暂定视口。等待 `document.fonts.ready`。
2. 先滚动整页，让懒加载图片和由滚动触发的内容出现。Playwright 的整页截图不会替页面触发滚动加载，这一点有 2026 年 5 月的公开问题说明。
3. 用计算样式读取字号、字重、行高、宽度。行高若返回像素，除以字号得到比值；若返回无单位数，直接使用。行高的像素值对应行盒，不等于行内文字的墨迹盒，不能用文字盒子高度代替行高。
4. 用元素边界检查对齐、间距、相交和是否伸出视口。横向溢出要排除宽度或高度为 0 的元素、被祖先裁切的元素，并给 1px 取整余量。伪元素和固定定位元素要另查。
5. 用文本范围的行盒估算每行字数。这一步的行切分需要在真实页面上验证。
6. 每个角度产出证据表：位置、数值、截图、建议严重度。人按第 3.5 节定分。多模态模型可以先写层级描述，描述必须指到具体位置；人决定 4 分和 5 分的差别，以及错位是否故意。

**能确认。** 计算字号、行高比、盒子、溢出、两个视口的重排。  
**不能确认。** 文字烧进图片时的真实字号；伪元素溢出可能漏检；“故意的风格化错位”仍由人判断。  
**取舍。** 需要可运行页面和浏览器环境。工程量集中在取证脚本和证据表，不需要训练模型。

### 4.2 路线 B：只有截图时的结构观察

**适用。** 只有整页图片，没有可打开页面。

**实现。** 按视口高度把长图切成连续屏幕，保留节与节的接缝。可用两种开放工具产生盒子，二者都不打分：

- PaddleOCR 的 PP-StructureV3，仓库 Apache-2.0。它检测标题、段落、表格等区域并给出坐标，坐标比纯识别模型更细。它面向文档，不是营销落地页。大图首屏、不规则卡片可能被切错。
- 微软 OmniParser，把界面截图解析成文字和可交互区域的盒子，原用途是界面操作代理。长落地页需要切片。本次检索确认项目和论文存在，没有核到许可证全文，使用前要自行确认。

盒子出来后，用同一套对齐、间距、重叠规则做几何检查。层级和“是否形成空间系统”由多模态模型按本标准举例，再由人定分。

**能确认。** 可见的对齐、大块间距、明显重叠、可见的标题大小差异。  
**不能确认。** 计算行高、精确字号、未提供的另一个视口、懒加载前不存在的内容。缺视口时按未判定处理。  
**取舍。** 不依赖页面源码。误切会直接污染证据，所以模型分段结果必须能叠回原图由人抽查。

### 4.3 路线 C：计算美学指标只作线索

Miniukovich 与 De Angeli 在 CHI 2015 提出对齐点数量、块尺寸种类、留白等自动指标。桌面网页研究中，包含这些指标在内的模型最多解释约 49% 的美学评分方差。指标还混合了排版以外的因素。

因此可以计算对齐点数量和同类块尺寸种类，帮助路线 A、B 找到可疑区域。不可以把指标线性映射到 1–5 分，也不可以因为分数相关就降低第 3 节的判断标准。

### 4.4 推荐与验证

有可打开页面时用路线 A。只有截图时用路线 B，并接受未判定。路线 C 永远不单独出分。

验证先做 10 页人工对照：脚本找到的溢出、重叠、行高比，必须和浏览器检查器一致；漏掉的伪元素溢出要记入已知缺口。美学分数是否稳定，只通过第 3.7 节的人工试评检验。

设计源文件若存在，可以另做字号和间距样式提取。本次没有核查设计工具 API，不把它算作已完成选型。
