# 落地页阅读层级评测

只评阅读层级：标题、说明、正文、行动文字是否用字号、字重和位置排出可扫描的顺序，以及这个顺序是否沿整页重复。

分数来自 `references/rubric.md`，不来自测量脚本。脚本只提供证据。

## 输入

一个 HTML 落地页文件。用户给路径就用路径；把 HTML 贴进对话时，先存成临时 `.html` 再测量。

默认两个视口都测。用户声明只评桌面时，加 `--desktop-only`，手机记不适用。

缺少可打开的 HTML 时不要估分，先要文件。

## 测量

在本 skill 的 `scripts` 目录执行。依赖未安装时先安装，不要下载 Playwright 自带浏览器，使用本机 Chrome：

```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
node measure_hierarchy.mjs "/绝对路径/页面.html"
```

脚本失败时，报告写未判定，附上 stderr 的原因。未判定不是 0 分。不要改用肉眼猜字号。

## 定分前

先读 [references/rubric.md](references/rubric.md)。档位边界不清楚时再读 [examples.md](examples.md)。

用证据做这些判断，不要把 `tiers` 数组的行数直接当成角色档数：

- 导航和按钮短标签可以证明首屏有行动文字，不能当成节标题或正文档。
- 首屏只看纵坐标小于视口高度的块。整页都很短时，后面的节也会落在首屏里，仍按 `container` 把主标题和节标题分开。
- 字号接近时，用字重和纵坐标判断还能不能分出先后。
- `heroTextMayBeInImage` 为真时，不要给首屏主标题编造字号。整页因此缺少必要证据则未判定。
- 行高、行长、对齐、间距、溢出即使出现在页面上，也不写入本分的降档理由。

## 输出

对话里给出完整报告，并写入 HTML 同目录的 `<文件名>-阅读层级评测.md`。使用这份结构：

```markdown
# 阅读层级评测

页面：
标准：落地页排版评测标准 v0.1，角度 A 阅读层级。本分不是整页排版分。
视口：桌面 1440×900；手机 390×844
页面状态：字体就绪后的稳定整页

## 检测结果

### 字号阶梯
（角色、字号、字重、出现位置、是否沿各节复用。角色名只用：主标题、辅助说明、节标题、正文、行动文字。）

### 首屏阅读顺序
（按纵坐标列出，每项附字号和字重。）

### 各节进入方式
（每节的节标题字号/字重，以及和阶梯是否同一角色。）

### 失效位置
（没有则写「无」。有则写到节，并给出该处的字号、字重和位置。）

## 评测分值

阅读层级分：（0–5 或未判定）
档位：（标准里的档名；未判定则写未判定）
严重度：（无 / 轻微 / 明显 / 严重 / 阻断）
定分理由：（命中了哪一条就停在哪一条。写明为什么不是相邻的上一档和下一档。）

## 评测标准依据

（引用判断目标、严重度定义和定分顺序中实际用到的条款。写明行距、对齐、间距、溢出未计入。）

## 改进结论

（只改字号、字重和位置，不改文案。每一条指向具体的节，并说明要回到哪一个已有角色。5 分写不必改。未判定只写还缺什么证据。）
```

报告末尾用一句话说明：此分为候选标准下的阅读层级分，未经样本校准。
