# 美学评测脚手架

把设计评测交给智能体时使用的任务说明。给定一个设计维度、一种设计物料，或两者都给，智能体按本说明产出可继续实施的评测方案，而不是套用一份现成的设计评分表。

## 怎么用

把 [`美学评测脚手架.md`](美学评测脚手架.md) 交给智能体，并提供以下一项或两项：

- **设计维度**：要研究什么，例如排版、配色。
- **设计物料类型**：要评什么，例如演示文稿、海报、产品界面。

可以这样开始：

> 我想为【设计维度】建立评测标准，物料是【类型】。

只知道其中一项也可以开始。只有业务目标、经营问题或效果诉求时，先补充维度或物料，不据此展开一套业务评价体系。

## 会得到什么

按设计维度组织，三项结果彼此对应：

1. **评测角度**：看什么、为什么和这个维度的质量有关、适用于哪些物料或状态。
2. **评测标准**：逐角度的执行规则、满分五分的分值判据、整个维度的定分方法，以及证据不足时如何处理。
3. **检测技术方案**：怎样取得证据。可以是模型、开源工具、规则或人工判断，并写明各自覆盖不到的地方。

标准与评分写在一起。不默认给每个角度打分再取平均，也不把风格相似、工具跑通或业务效果好当成美学质量高。

没有样本校准时，结果标为候选，不能当作已经验证的标准。

同一套质量边界有两种用法：

- **美学产物评测**：检查完整产物，记下问题，用来改进后续生产能力。
- **美学 Loop 评测**：交付前检查、修改并复查这一次的完整产物。需要事先限定修改范围、时间、成本和次数。

## 测试示例

这次试跑只做落地页的排版，并且检测技能只覆盖其中的「阅读层级」。配色、图形、文案、品牌识别、转化效果，以及行距、对齐、间距、溢出，都不进入这一分。

测量脚本在 `测试示例/skills/landingpage-reading-hierarchy/scripts`。它只用本机 Chrome 取字号、字重和位置，分数仍按标准判定。依赖没有放进仓库，使用前在该目录执行：

```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
node measure_hierarchy.mjs "/绝对路径/页面.html"
```
